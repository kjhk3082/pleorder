# Gleo 주문 호출과 차량 UI 검증

**2026년 11월 15일 · 플레오더 0.2.2 (versionCode 4)**

0.2.1 APK에서 `GleoActionActivity`와 `GleoReceiver`의 `android:enabled` 값은 실제로 `false`였다. 공모전 공지를 다시 확인해 출품판의 두 진입점을 활성화했다. 참가팀은 별도 승인 없이 App Schema를 사용할 수 있다. 차량이 “플레오더” 호출어와 스키마를 해석하고, 앱은 주문 처리 결과를 Gleo에 응답한다. [공식 개발 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008) · [App Schema](../../app/src/main/assets/schema.json)

## 실제 장치에서 무엇을 시험했나

Pleos Connect 2.1.0 / Android 14 API 34, x86_64 / Gleo 4.2.0.15. 제출용 release를 설치한 읽기 전용 AVD에서 차량 설정을 열었다. Android의 기본 음성 비서를 `cmd voiceinteraction show`로 열고, 에뮬레이터 가상 마이크로 한국어 합성 음성을 재생했다. 앱 함수에 텍스트나 ADB 주문 인텐트를 직접 보내지 않았다. 이 방식은 차량 음성 버튼 이후의 인식과 함수 호출을 확인한다. 호출어 감지와 실차 마이크 품질은 별도 검증 대상이다.

| 차량에서 말한 내용 | Gleo가 선택한 동작 | 플레오더 결과 |
| --- | --- | --- |
| 치킨 한 마리를 우리 집으로 배달해 주세요 | `PREPARE_FOOD_ORDER` | 차량 설정에서 플레오더로 전환. 치킨 1개, 현대카드 M, 21,000원 견적을 제시했다. |
| 방금 담은 주문을 이대로 결제해 줘 | `CONFIRM_FOOD_ORDER` | `PO-0002`가 21,000원으로 한 번 승인됐다. 앱에서도 결제 영수증을 확인했다. |
| 가장 최근 주문 상태를 알려 주세요 | `GET_FOOD_ORDER_STATUS` | 차량 설정에 그대로 머물렀다. 같은 `PO-0002`, 같은 금액, 조리 중, 배달까지 약 26분으로 응답했다. |

[실제 Gleo 영상](../../산출물/02_시연영상/플레오더_Gleo_실기시연.mp4) · [한국어 장면 자막](../../산출물/02_시연영상/플레오더_Gleo_실기시연.srt). 0:00–1:18의 세 장면은 같은 설치와 같은 주문에서 촬영했다. 1:18부터는 주행 조건을 바꾼 별도 회차다. 첫 발화는 비서가 앱 이름을 잘못 인식해 차량 설정에 머물렀다. 영상은 운전자가 다시 말한 성공 발화부터 시작하며, 응답에 맞춰 대기 시간을 편집했다.

다른 시험에서는 교촌치킨 26,000원이 승인되고 같은 주문을 조리 중·약 28분으로 조회했다. 첫 승인에서는 주문 엔진 준비 지연이 발생해 다시 말해야 했다. 견적을 낸 직후 백그라운드 주문 엔진을 준비하도록 수정한 뒤 위 21,000원 회차의 승인 요청은 첫 시도에서 성공했다. 이전 21,500원 주문에서는 여러 주문이 쌓여 있을 때 주문 번호를 다시 물었다. 가장 최근 주문·메뉴·정확한 주문 번호의 조회를 검증하는 회귀 검사를 추가했다.

공식 Virtual Console로 최종 0.2.2의 P → D 정차 → D 30km/h → P 전환을 점검했다. D 두 상태 모두 플랫폼 `requiresDistractionOptimization=true`, 제한 값 80(`0x50`)과 플레오더 `DrivingActivity`가 확인됐고 P에서 매장 탐색 화면으로 돌아왔다. D단·30km/h 시험 입력을 유지한 별도 회차에 시스템 Gleo로 강남구청 배달 견적 26,000원을 열고 현대카드 M으로 승인했다. 다른 화면에서 같은 모의 주문의 조리 중·남은 26분을 조회했다. 실기 영상 1:18에서 주행용 UI의 견적과 승인을 볼 수 있다.

**배송지 음성 입력.** Gleo에서 강남구청을 검색해 두 후보를 받았고, 1번을 선택해 앱 배송지를 강남구청으로 변경했다. 가상 동·호수는 `SET_DELIVERY_ADDRESS_DETAIL`이 **101동 202호**를 다시 읽으며 `asking`을 반환했다. 이어 “방금 확인한 첫 번째 주소로 저장해 줘”를 말했을 때 `CONFIRM_DELIVERY_DESTINATION`이 `success`와 같은 동·호수의 저장 결과를 돌려줬다. 검색·장소 선택과 최종 동·호수 확인은 두 녹화에 걸쳐 같은 앱 배송지를 사용했다. 차량 내비 목적지는 그대로 유지됐다.

이전 시험에서 “202호”를 “201호”로 인식한 사례가 있었다. 최종 APK는 첫 발화로 기존 호수를 덮어쓰지 않는다. 확인 응답의 선택적 숫자 필드가 비어 있어도 기존 제안을 유지하고, 삭제는 별도의 명시적 요청으로 처리한다. 숫자 정정·취소·만료·재시작·배송지 변경을 포함한 자동 검사 144개가 통과했다. 앱 이름도 일부 발화에서 “블랙오더”로 인식돼 다시 말해야 했다.

## UI를 다시 확인한 항목

플레오더는 주차 중 메뉴·리뷰·설정을 보여 준다. 주행 제한 시에는 차량이 제공한 `CarUxRestrictions`에 맞춰 음성·확인 금액·카드·진행 상태만 제공한다. 음성 시작은 차량 버튼 또는 **Gleo로 말하기** 한 번이다. 차량에서 비서 화면을 열 수 없으면 공개 Pleos STT로 연결한다. 주행 화면에는 자동으로 움직이는 지도·반복 애니메이션·텍스트 자동 스크롤이 없다. [Pleos Connect UI 디자인 가이드](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro) · [주행 안전을 고려한 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

| 화면 검수 | 결과 |
| --- | --- |
| 1280 × 720, 900 × 600 | 주 음성 버튼 높이 88 CSS px, 현황 버튼 76 CSS px. 두 크기에서 주 음성 버튼 전체 노출과 가로 넘침 0을 확인했다. |
| 야간 보조 글자 | 어두운 패널의 안내·상태 문구가 8.92:1. 원본 P 심벌은 밝은 받침을 둬 야간에도 모양이 드러난다. |
| 주간 보조 글자 | 밝은 패널의 보수적 배경색 추정에서 두 문구 모두 5.39:1 이상. 공식 지침의 대비 기준은 4.5:1이다. |
| 터치 피드백과 주행 | 누르면 바로 연결 안내를 표시한다. 글이 길면 3줄, 작은 높이의 피드백은 2줄로 제한한다. |

크기·대비는 브라우저에서 실제 주행 화면 DOM과 계산된 스타일로 측정했다. 차량 디스플레이의 물리적인 글자 높이, 실제 운전자 시선 체류 시간, 안전 인증을 측정한 수치는 아니다.

## 재현

1. [릴리스](https://github.com/kjhk3082/pleorder/releases/tag/contest-2026-11-15-gleo)에서 다운로드해 P단에서 설치한다. 기본 비서가 Gleo이고 음성 모델과 서비스가 준비된 에뮬레이터를 사용한다.
2. 차량 설정에서 Gleo를 열고 “플레오더에서 치킨 한 마리 집으로 배달해 줘”라고 말한다. 금액과 수단을 확인한다.
3. “플레오더에서 방금 담은 주문을 결제해 줘. 결제를 승인합니다”라고 명시한다. 음성이 다른 이름으로 인식되면 견적을 다시 확인한다.
4. 차량 설정에서 “플레오더 주문 상태 알려 줘”라고 말하고 동일 주문 번호·금액과 진행 상태를 확인한다. 시험 데이터 초기화는 앱 상단 DEMO에서 한다.

앱의 Gleo 이벤트는 `adb logcat -s PleorderGleo`로 확인할 수 있다. 단말 로그 시간은 에뮬레이터 시각이다. 원시 로그에는 사용자 정보가 포함될 수 있어 이 기록에는 함수명, 모의 금액과 상태만 남겼다.
