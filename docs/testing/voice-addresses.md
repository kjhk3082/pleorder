# Gleo 목적지·상세주소 입력

## 구현

- `SEARCH_DELIVERY_DESTINATION`: 저장한 장소 또는 Photon 실제 장소 검색. 검색만으로 배송지를 바꾸지 않는다.
- `CONFIRM_DELIVERY_DESTINATION`: 사용자가 말한 번호/확인으로 선택. 거절, 잘못된 번호, 3분이 지난 결과는 기존 배송지를 유지한다.
- `SET_DELIVERY_ADDRESS_DETAIL`: 동·호수·층·로비를 저장하고 Gleo가 다시 읽는다. 선택 중인 장소가 있으면 그 장소에 연결한다.
- 세 액션은 주차·주행·화면 없는 백그라운드에서 같은 구현을 사용한다. 주소 마이크 버튼도 `showAssist()`로 Gleo를 연다.
- 동·호수는 지도 검색어에서 분리한다. 음성 해석과 확인 응답에는 Gleo를 사용하므로 ‘음성 데이터도 완전 로컬’이라는 뜻은 아니다.
- 목적지 변경은 앱의 배달받을 곳을 변경한다. 차량 내비게이션 경로를 자동 변경하지 않는다.
- 진행 중인 주문/결제 확인이 있으면 주소 변경을 거절한다. 미결제 주문의 주소를 바꾸면 이전 결제 승인을 폐기한다.

## 추가 수정

| Before | After | Why |
| --- | --- | --- |
| 주소 마이크가 오류가 나는 독립 STT를 호출 | 주문과 같은 Gleo 호출 | 실제 동작하는 음성 경로로 통일 |
| 구청 검색에 지하철역·자전거 대여소 노출 | 시설 유형 필터와 후보 정렬 | 같은 이름의 다른 지점을 배송지로 오인하지 않도록 함 |
| UI/음성별 주소 변경 코드 중복 | 공통 저장·검증·장바구니 재계산 | 수령 방식·요청사항 유지, 오래된 승인 무효화 |
| Windows PowerShell에서 빌드 경로 계산 실패 | 지원되는 문자열 상대 경로 계산 | PowerShell 5.1/7 모두 빌드 가능 |

지도 데이터에 없는 건물이나 불완전한 도로명주소는 여전히 있을 수 있다. 후보를 읽어 주고 확인하며, 없는 주소나 좌표를 만들어 저장하지 않는다.

## 재현

`tools/New-SpeechFixtures.ps1` 실행 후 `tools/Test-GleoVoice.ps1 -Case addresses -Background`.
강남구청 검색 → 1번 선택 → 101동 202호 → 102동 1002호로 정정 → 다른 숙소 검색 → 선택 취소를 검사한다.
실제 Gleo 음성 인식·함수 호출·음성 응답 경로를 사용하며 입력은 Windows 한국어 합성 음성이다. 원래 앱 상태는 검증 후 복원한다.

콜백은 [공식 가이드](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/action_callback)의 7초 제한 안에서 응답하도록 지도 검색을 3.5초로 제한한다. 외부 검색 실패 시 이전 배송지는 유지한다.

## 실제 검증 결과 · 2026-11-09

D단 0km/h에서 다른 앱을 전면에 둔 실제 Gleo 음성 경로:

| 발화 | 결과 |
| --- | --- |
| 강남구청으로 배달 목적지 검색 | 관공서 후보 1개, 기존 주소 유지 |
| 1번 선택 | 강남구청으로 변경 |
| 101동 202호 입력 | `101동 202호` 저장 |
| 102동 1002호로 수정 | `102동 1002호` 저장 |
| 롯데호텔 L7 홍대 검색 | 새 후보 1개, 기존 주소 유지 |
| 방금 검색한 장소 선택 취소 | 강남구청 및 상세주소 유지 |

모든 단계에서 주문/결제 0건. 사용자 원래 상태는 복원했다.
별도 주차 화면의 상세주소 마이크를 UI 트리로 찾아 직접 클릭해 `ASSIST_REQUEST shown=true` → `SET_DELIVERY_ADDRESS_DETAIL` 성공 → `101동 202호` 저장도 확인했다. 이 확인은 합성 음성을 에뮬레이터 마이크에 넣은 것으로 사람의 실제 발성·도로 주행 검증은 아니다.

음성 결과에 따라 주소와 주변 매장 목록이 갱신됨을 화면에서 확인했다. 상세주소 지우기, 미확정 장소 결과 만료 시 이전 집 주소를 잘못 수정하지 않기, 일반 주소창 복귀 시 입력 유지도 보완했다.
