# 플레오더 시나리오 목록

실제 지도 좌표, 가상 매장과 모의 거래를 사용합니다. 시나리오 선택은 앱 우측 상단 실험실 버튼에서 할 수 있습니다.

| ID | 구분 | 시나리오 | 기대 결과 |
|---|---|---|---|
| delivery-home | 배달 | 퇴근길 집으로 배달 | 비빔밥을 집으로 주문하고 라이더의 이동을 확인해요. |
| delivery-arrival | 배달 | 내 도착에 맞춰 배달 | 귀가까지 50분. 조리 시작을 조정해 배달 시점을 맞춰요. |
| family-order | 배달 | 함께 먹을 저녁 | 같은 매장 메뉴를 여러 개 담고 수량과 합계를 확인해요. |
| pickup-route | 픽업 | 가는 길에 픽업 | 매장을 경유지로 추가할지 확인하고 집까지 이어서 안내해요. |
| pickup-direct | 픽업 | 가까운 매장 픽업 | 가까운 코너버거에서 주문하고 직접 수령해요. |
| switch-mode | 주문 변경 | 배달에서 픽업으로 | 확정 전 수령 방식을 바꾸고 배달비가 빠지는지 확인해요. |
| sold-out | 예외 상황 | 선택 메뉴 품절 | 비빔밥이 품절이에요. 다른 메뉴를 안내해요. |
| closed | 예외 상황 | 매장 영업 종료 | 소담한상 영업이 끝났어요. 다른 매장에서 주문해요. |
| outside-area | 예외 상황 | 배달 지역 밖 | 배달할 수 없는 목적지예요. 픽업으로 전환할 수 있어요. |
| delay | 예외 상황 | 조리가 늦어질 때 | 조리가 10분 늦어져요. 갱신된 도착 시간을 확인해요. |
| offline-map | 복구 | 지도 연결 끊김 | 배경지도 대신 저장된 도로 경로를 사용하고 주문 상태는 유지해요. |
| no-destination | 복구 | 집이 설정되지 않음 | 배달 전 목적지를 선택해요. 픽업은 계속 이용할 수 있어요. |
| speech-retry | 복구 | 음성을 못 알아들었을 때 | 짧은 예시를 보고 다시 말하거나 화면에서 선택해요. |
| cancel-early | 주문 변경 | 조리 전 주문 취소 | 주문 직후 취소하면 진행이 멈추는지 확인해요. |
| cancel-late | 주문 변경 | 조리 후 취소 요청 | 조리 시작 후에는 자동 취소하지 않고 안내를 보여줘요. |
| relaunch | 복구 | 앱을 다시 열었을 때 | 앱을 종료하고 열어도 주문과 진행 상태가 복원돼요. |
| duplicate | 복구 | 확정이 두 번 들어오면 | 같은 확인 요청을 다시 보내도 주문은 하나만 생성돼요. |
| payment-insufficient | 결제 | 결제 잔액·한도 부족 | 테스트카드 승인이 거절돼요. 다른 수단으로 바꿔 다시 확인해요. |
| card-declined | 결제 | 카드사 승인 거절 | 원인을 단정하지 않고 다른 수단이나 카드사 확인을 안내해요. |
| payment-pending | 결제 | 결제 결과 미확인 | 결과 조회 전 재결제하지 않아 이중 결제를 방지해요. |
| merchant-reject | 매장 | 매장이 주문을 거절 | 주문을 취소하고 원래 결제 수단으로 환불 대기를 안내해요. |
| merchant-cancel | 매장 | 조리 중 매장 취소 | 매장 사정으로 조리 중 취소된 주문과 환불 내역을 확인해요. |
| rider-delay | 배달 | 라이더 배정 지연 | 음식은 준비됐지만 라이더가 없어 배달 시작으로 표시하지 않아요. |
| rider-reassigned | 배달 | 라이더 재배정 | 기존 배정 취소를 알리고 새 라이더가 연결될 때까지 기다려요. |
| recipient-unavailable | 배달 | 도착했지만 수령인 부재 | 배송 완료로 넘기지 않고 수령 가능 확인을 기다려요. |
| pickup-no-show | 픽업 | 픽업 시간이 지났을 때 | 준비 후 30분이 지나면 수령 안내를 보내요. 자동 완료하지 않아요. |
| refund-delay | 결제 | 환불 처리 지연 | 취소와 환불 완료를 구분하고 환불 대기 금액을 보여줘요. |
| missing-item | 고객 지원 | 배달 뒤 누락 신고 | 누락 접수와 확인 대기를 기록하고 임의로 환불을 완료하지 않아요. |

## 공통 절차

1. 시나리오 선택 → 메뉴 선택 또는 음성 입력
2. 수량·배달/픽업·결제 수단·총액 확인
3. 모의 주문 확정
4. 실험실의 +5분 또는 재생으로 상태와 상세 내역 확인
5. 앱 재실행 후 주문·결제·환불 상태 복원 확인

모든 시나리오를 사람 음성 및 실제 Gleo 클라우드로 끝까지 검증했다는 뜻은 아닙니다. 검증 기록은 verification.md에 구분합니다.
