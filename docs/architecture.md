# 플레오더 구현과 서비스 전환

## 거래와 주문을 분리

결제는 `pending → paid / failed → refund_pending → refunded`, 주문은 `accepted → cooking → waiting_rider / delivering / ready → completed`로 관리한다. 매장 취소와 고객 취소는 주문을 `cancelled`로 만들고 별도의 환불 상태를 생성한다. 수령인 확인은 `contact_needed`, 누락 문의는 별도 support 기록이며 임의 환불 성공으로 바꾸지 않는다.

결제 멱등성의 기준은 주문 초안 ID다. 결제 수단 변경으로 같은 초안에 두 번 청구하지 않는다. 결과 미확인 거래가 있으면 초안을 폐기하거나 새 결제를 시작할 수 없다. 승인 조회가 늦어져도 이미 결제된 초안을 단순 만료시켜 버리지 않는다.

확정은 현재 초안 ID와 명시적인 동의를 요구한다. 품절, 영업 종료, 배달 불가, 범위 밖 수량은 확정 전에 거절한다. 부정 발화는 결제·수령 처리보다 먼저 판단한다. 로컬 한국어 해석기는 제한된 명령용이며 범용 LLM이 아니다.

## UI와 실제 장치

Android Java 호스트가 번들 UI를 제한된 HTTPS origin에서 제공한다. 외부 페이지 이동, file/content 접근, mixed content를 차단한다. JavaScript 인터페이스는 앱 번들에서만 사용한다. 릴리스 빌드에서는 WebView 원격 디버깅과 QA PCM 입력을 사용할 수 없다.

STT와 TTS는 오디오 포커스·세션 세대 번호로 오래된 콜백을 무시하고, 종료 시 UI 상태도 갱신한다. 사용자가 마이크를 누르면 읽기를 중단한다. 자동 상태 안내도 현재 인식 중인 발화를 덮지 않는다.

주행 중 시스템 제한을 해제하지 않는다. CarUxRestrictions를 구독하며 앱 카테고리를 다른 것으로 가장하지 않는다. 주차 상태로 화면을 테스트한다.

## 교체 지점

- `PaymentRepository`를 서버 거래 어댑터로 교체: 카드 토큰, 결제 승인·조회·취소 Webhook, 서버 멱등성 키, 감사 로그가 필요하다. 실제 PAN/카드 비밀 정보는 앱에 저장하지 않는다.
- `OrderRepository`의 매장 접수·조리·배달 이벤트를 주문 서버 이벤트로 교체한다. 현재의 가속 시계는 데모 전용이다.
- OSM 공개 타일과 OSRM 데모 경로를 운영 지도/경로 서비스로 교체한다. 실제 교통·역지오코딩·주소 검증·차량 현재 경로의 목적지 동기화가 필요하다.
- Gleo 스키마 검토 및 활성화 후 실제 클라우드 대화를 테스트한다. 직접 내부 LLM 엔드포인트를 사용하거나 다른 앱의 자격 증명을 빌리지 않는다.
- 실서비스 배포 전: 서버 권한 검증, 주문·결제 이벤트 재처리, 지원 운영, 실제 주소/개인정보 보관 정책, 모니터링·성능·접근성·장시간 주행 검증이 필요하다.

현재 결과물은 위 경계를 갖춘 **제품 시뮬레이터**다. 실제 주문·결제 서비스 운영이나 모든 예외 상황의 검증 완료를 의미하지 않는다.
