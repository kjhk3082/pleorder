# 플레오더 v7: 주문·결제·배송 중심

이번 변경은 기존 배달/픽업과 실제 Pleos 어댑터를 유지하며 일반 사용자 화면에서 실험실·장식 문구를 제거한다. 회귀 시나리오는 개발자 API에만 남긴다.

1. 목적지/현재 위치/집 주변 필터, 지역과 최근 주문을 활용한 추천. “치킨 먹고 싶어”는 최근 치킨 매장 제안이며 즉시 결제하지 않는다.
2. 인카페이먼트와 배달앱 등록 카드가 구분된 월렛. A는 충분한 한도, B는 한도 0, C는 승인 확인/거절 상태. 결과는 카드 데이터에서 결정된다. 등록·해제·기본 수단 선택 및 빈 월렛 복구를 제공한다.
3. 수량·주소·전달 방식·요청사항·카드·금액을 확인한 뒤 화면에서는 끝까지 밀어서 결제한다. 음성에서는 명시적인 결제 승인만 수락한다. 카드 변경/초안 변경 시 슬라이드 확인은 초기화된다.
4. 지도는 주문 단계에 맞춰 배송지/라이더를 크게 보여 준다. 현 위치/배송지 버튼의 의미를 텍스트로 표시한다. 광역 전체 매장 표시를 기본으로 하지 않는다.
5. 배송 ETA와 완료 시각을 구분하고, 문 앞 전달은 샘플 증빙 사진을 함께 표시한다. 미수령/누락 신고로 이어진다.
6. 결제 성공 체크, 거절 피드백, 패널 전환, 상태 전환, 5초마다 바뀌는 음성 예시를 제공한다. reduced-motion을 존중하며 화면 사용은 차량 제약을 따른다.

참고: [현대 공식 인카페이먼트 주문 안내](https://update.hyundai.com/KR/KO/updateNoticeView/lV1HTP), [배민 앱](https://apps.apple.com/kr/app/id378084485), [배민 화면 기록](https://wwit.design/2021/03/26/baemin/). 오래된 화면은 구조 참고이며 현재 앱과 동일하다고 주장하지 않는다.

실제 인카페이먼트 SDK를 연결한 것으로 표시하지 않는다. 카드 번호·CVC·비밀번호를 받지 않고 준비된 테스트 카드만 등록한다. 매장은 OSM 실제 장소 데이터이며, 메뉴는 공식 출처가 있는 항목과 테스트 항목을 구분한다. 최근 주문 초기 예시·배달 진행·증빙 사진은 시뮬레이션이다.

## 모션과 검토

[Emil의 원칙](https://emilkowal.ski/ui/great-animations), [공유 레이아웃/Family 사례](https://animations.dev/gallery), [선택 탭 사례](https://motion.dev/examples/js-tab-select)를 참고했다. 코드/유료 강의를 복제하지 않고 Web Animations API와 CSS로 작성했다.

| Before | After | Why |
|---|---|---|
| 고정된 시나리오 카드가 일반 흐름에 노출 | 카드 데이터와 매장 이벤트로 결과 발생, 테스트 API만 분리 | 사용자가 테스트 케이스를 고르지 않음 |
| 용도를 알기 어려운 지도 아이콘 | 현 위치 / 배송지 텍스트 버튼 | 행동 결과를 예상할 수 있음 |
| 매 갱신마다 목록 교체 | 같은 목록/상태는 유지하고 변경 때만 모션 | 깜빡임과 반복 애니메이션 방지 |
| 단순 완료 문구 | 총액/카드/예정시각과 체크 애니메이션 | 결제 결과를 분명하게 확인 |
| 넓은 범위의 고정 지도 | 배송 단계에 맞춰 라이더·수령 장소 프레이밍 | 배송 위치를 읽을 수 있음 |

모션: 선택 탭 공유 배경, 목록 순차 등장, 수량 피드백, 모달 본문 방향 전환, 결제 체크, 주문 단계/ETA 변경, 지도 라이더 보간. 이동·투명도 위주이며 reduced-motion을 반영한다.
