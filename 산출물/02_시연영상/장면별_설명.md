## 녹화와 편집 범위

실제 Pleos 에뮬레이터를 ADB로 녹화했습니다. 설명 자막과 Windows 한국어 합성 내레이션을 추가했습니다. 음성 SDK 장면은 가상 마이크에 주입한 합성 시험 음성과 실제 에뮬레이터 스피커의 TTS 응답을 함께 담았습니다. 사람 목소리·실차 테스트가 아닙니다. 시간 가속과 목적지 상태 이벤트 주입을 해당 장면에 표시했습니다. 내비게이션 장면은 전송 확인창까지입니다. 정체 장면은 독립된 도착정보 시험 입력과 시계 가속을 사용합니다. Gleo 연결 카드는 향후 기획이며 실제 연동 화면이 아닙니다. 음성 장면은 11월 12일 debug 기록이며 새 release의 반복 검증을 의미하지 않습니다. 주문·결제·라이더·문 앞 사진은 시뮬레이션입니다.

메뉴·설정 장면은 주차 상태이며, 주행 제한과 Gleo 승인 범위는 검증 문서를 참고하세요. 모든 예외 상황이 영상에 포함되어 있지는 않습니다. 예외·개인화·다중 주문 등은 회귀 검사와 별도 검증 문서에서 확인할 수 있습니다.

## 내레이션

### 01   목적지와 경로를 기준으로 찾기

플레오더는 차량의 목적지와 도착 시간을 음식 주문에 연결하는 앱입니다. 집 주변, 내 주변, 가는 길을 구분합니다. 가는 길에서는 매장까지 거리와 시간, 경유에 추가되는 부담을 확인할 수 있습니다. 출발지와 배송지는 바꿀 수 있습니다. 지금 화면의 매장과 주문은 시연용 구성입니다.

### 02   공개 매장 정보와 공식 브랜드 메뉴

실제 매장 모드에는 서울의 공개 지도 데이터를 연결했습니다. 교촌 매장의 메뉴는 공식 브랜드 자료와 권장 가격을 사용합니다. 매장 정보와 리뷰 탭을 분리했으며, 확보하지 않은 리뷰를 만들지는 않습니다. 지점별 판매 메뉴와 배달 가능 여부는 별도 확인이 필요합니다.

### 03   배송지 검색과 지도에서 선택

배달받는 곳은 집에 고정되지 않습니다. 장소 이름이나 도로명주소로 검색한 뒤 지도에서 위치를 확인합니다. 여행 중인 호텔이나 다른 목적지도 지정할 수 있습니다. 검색 후보를 확인하고 상세주소를 입력한 다음 저장하는 흐름입니다.

### 04   메뉴 구성과 결제 전 확인

같은 매장의 메뉴를 여러 개 담고 수량을 조절합니다. 주문 확인 화면에는 배송지, 요청사항, 메뉴 금액, 배달팁과 총액이 나옵니다. 인카페이먼트와 배달 앱 카드 구성을 구분하되, 이 시연의 결제는 모두 실제 청구가 없는 시뮬레이션입니다.

### 05   결제 거절과 재승인

실패도 정상적인 흐름으로 다룹니다. 테스트 한도가 없는 신한카드로 밀어서 승인하면 결제가 거절됩니다. 이후 현대카드로 변경하고 사용자가 다시 승인해야 주문이 생성됩니다. 성공 화면에서 총액과 카드, 예상 도착 시각을 확인할 수 있습니다.

### 06   조리부터 배달 완료까지

주문 확인, 조리, 배달, 완료까지 진행 상태를 추적합니다. 라이더와 차량의 이동은 지도 위의 시뮬레이션입니다. 완료 시각과 문 앞 사진을 함께 보여 줍니다. 이 장면은 긴 대기 시간을 줄이기 위해 테스트 시계를 단계적으로 앞당겼습니다.

### 07   가는 길 픽업과 수령 완료

픽업은 드라이브스루와 별개인 매장 방문 수령입니다. 경유 거리와 시간을 확인하고, 배달팁 없이 모의 결제합니다. 내비게이션 전송은 사용자가 따로 확인합니다. 이 영상은 전송 확인창까지만 보여 줍니다. 시험 시계를 앞으로 이동하면 음식 준비가 완료됩니다. 실제로 음식을 받은 뒤 픽업 완료라고 알려 주면 주문을 마칩니다. 이 장면의 명령 입력은 시험용 텍스트이며 음성 인식 검증이 아닙니다.

### 08   정체로 도착이 늦어질 때 예약 전송 조정

도착 맞춤 주문은 먼저 모의 결제를 확인하고 매장 전송을 기다립니다. 이제 차량 정체로 도착 예상이 60분에서 75분으로 늘어나는 상황을 입력합니다. 앱은 아직 보내지 않은 주문의 전송을 15분 늦춥니다. 추가 결제는 없습니다. 원래 전송할 시점이 지나도 대기하고, 조정한 시점에 딱 한 번 전송합니다. 이미 조리 중인 주문은 되돌리지 않습니다. 이 장면은 시험용 도착정보와 시간 가속을 사용하며 실시간 교통정보 수신 영상이 아닙니다.

### 09   도착 맞춤 예약과 보류·재개

도착 맞춤 주문은 결제와 매장 전송 시점을 구분합니다. 경로를 다시 확인해야 하는 상황에서는 예약을 보류합니다. 사용자가 기존 장소로 재개하면 같은 결제와 주소를 유지합니다. 이 장면은 목적지 상태 이벤트와 시간 가속을 주입한 예약 시뮬레이션입니다.

### 10   공개 Pleos 음성 SDK로 주문·승인·조회

별도 내레이션 없이 시험 입력과 실제 SDK 음성 응답을 재생합니다.

### 11   Gleo 호출에서 앱 연결까지 향후 계획

글레오에게 주문을 말하면 플레오더로 연결하는 흐름은 향후 승인 후 구현할 계획입니다. 현재 공모전은 참가팀의 글레오 인터페이스 승인 신청을 받지 않습니다. 그래서 이 화면은 기획 설명이며 실제 연동 성공 화면이 아닙니다. 현재 출품판은 앱 안에서 공개 음성 인식과 합성 SDK를 사용합니다.

### 12   카드 관리와 연속 음성 대화 설정

카드 관리와 설정도 준비했습니다. 실제 카드 번호는 받지 않습니다. 새로 추가한 음성 대화 이어가기는 주문 확인 안내가 끝난 뒤 마이크를 다시 열어 답할 수 있게 합니다. 화면을 닫거나 앱이 뒤로 가면 취소되고, 결제는 별도의 명시적 승인이 필요합니다. 실제 음성 반복 검증은 별도로 계속 진행합니다.

### 13   최종 release APK의 주행 화면 전환

최종 릴리스 에이피케이를 설치한 실제 에뮬레이터입니다. 디 단 정차와 시속 삼십 킬로미터에서 간결한 주행 화면을 유지합니다. 차량이 전달한 디오 요구와 제한 비트를 적용하며, 다시 주차하면 탐색 화면으로 돌아갑니다. 실차 안전 인증이나 모든 지역에서의 사용 승인을 의미하지 않습니다.
