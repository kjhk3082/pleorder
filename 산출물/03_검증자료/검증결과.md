# 출품본 검증 결과

**최신 확인일 2026-11-15 · 출품 APK 0.2.2 (versionCode 5)**

versionCode 5는 원본 P 로고와 공모전 제출용 사진 패키징을 적용한 설치본입니다. 아래 영상의 시스템 Gleo 녹화는 같은 0.2.2의 versionCode 4에서 진행했습니다.

저장소의 [서명 APK](../../apk/플레오더_플레오더_release.apk)는 102,151,867바이트입니다. 메뉴 사진 62장의 JPEG 인코딩을 조정했고 모든 사진의 원래 픽셀 크기를 확인했습니다. 이전·현재 APK는 모두 1,060개 항목을 담고 있습니다. 라이브러리, App Schema, 주문 화면의 HTML·CSS·JavaScript 및 지도 설정을 바이트 단위로 대조했습니다. APK v2 서명 검증과 Pleos API 34 기기 설치를 통과했고 `DrivingActivity`의 첫 실행과 설치된 versionCode 5를 확인했습니다.

이 설치본에서 P단과 D단 시속 30km로 Gleo 음성 주문을 다시 시험했습니다. 두 조건 모두 견적, 21,500원 모의 결제 승인, 같은 주문의 현황 조회가 차례로 성공했습니다. [콜백 기록과 주차·주행 화면](../../docs/testing/gleo-release-2026-11-15.md#제출-apk-재시험)

## 0.2.2 앞선 차량 Gleo와 주행 UI 시험

- 차량 설정에서 시스템 Gleo에 치킨을 주문하고, 플레오더가 현대카드 M과 총액 21,000원의 견적을 여는 과정을 촬영했습니다. 별도 음성 승인을 받으면 모의 거래를 생성합니다. 차량 설정을 보면서 같은 주문의 조리 상태와 잔여 시간도 조회했습니다. [시험 환경·결과·영상](../../docs/testing/gleo-release-2026-11-15.md)
- 주행 모드에서는 공식 콘솔의 D단·30km/h 시험 신호에서 강남구청 배달 26,000원 견적·승인·조리 중 조회를 확인했습니다. 별도 주소 시험에서 공공장소 검색, 후보 선택, 가상의 101동 202호 재낭독과 음성 저장까지 확인했습니다.
- 출품판 App Schema의 Activity와 Receiver가 활성화되어 있습니다. 공모전 참가팀은 별도 검토·승인 없이 Gleo Interface를 사용할 수 있습니다. [공식 개발 범위](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)
- 견적 만료에 실제 경과 시간을 적용하고, 차량 설정에서 승인한 거래를 주차 화면이 과거 상태로 덮어쓰던 오류를 수정했습니다. 자동 검사 144개가 통과했습니다.
- 야간 안내 글자 대비 8.92:1, 주간 5.39:1 이상을 확인했습니다. 두 화면 폭에서 음성 버튼과 현황 버튼의 높이와 가로 넘침을 점검했습니다. 현장 마이크와 실제 운전자의 시선 체류 시간은 별도의 시험이 필요합니다.

## 0.2.1 팀 피드백 반영 및 재검증

- DT 주문은 1차 제출 범위에서 제외하고 배달과 일반 매장 픽업을 유지했습니다. 공개 기획서와 비공개 접수양식에 반영했습니다.
- 연속 음성 대기, 45초 만료·취소·중복 종료 콜백 보호, 마이크 준비 피드백을 추가했습니다. 명시적 결제 승인은 유지합니다.
- 정체로 ETA가 바뀌면 미전송 예약의 전송 시각만 조정합니다. 실제 앱에 시험 ETA 60분→75분을 입력해 15분 지연, 기존 시점 대기, 최종 전송 1회·결제 1건을 확인했습니다. 이미 접수한 주문은 되돌리지 않습니다.
- 90초 이상 오래된 차량 ETA와 미래 타임스탬프는 전송을 보류합니다. 최신 ETA가 없으면 재개 성공으로 안내하지 않습니다.
- 픽업 준비→수령 완료까지 실제 앱을 촬영하고 completed 및 거래 1건을 확인했습니다. 내비 전송은 확인창까지 촬영했습니다.
- 11월 13일 `npm test`: **136개 통과, 실패 0**. debug와 release 빌드 성공. release 0.2.1 / versionCode 3 설치·서명·비밀값 비포함 및 개발 routeEndpoint 부재를 확인했습니다.
- 최종 release에서 공식 콘솔의 P→D 0km/h→D 30km/h→P 전환을 녹화했습니다. D 상태에서 실제 제한은 `0x50`이며 DO 화면이 유지됩니다. 모션 정지, 최대 3줄 요약, 큰 음성 버튼과 준비 상태를 적용했습니다. 실차 가독성·안전 인증을 뜻하지 않습니다.

## r2 추가 수정과 재검증

- 주소 모달 안에 마이크 준비·듣기·인식 결과·오류를 표시합니다. 숫자로 읽은 동호수를 정리하고, 백그라운드 상태 갱신이 편집 중인 상세주소를 덮어쓰지 않도록 수정했습니다.
- 주문·결제 및 대화 선택 창 안에 ‘말로 답하기’ 버튼을 추가했습니다. 버튼 클릭만으로 결제하지 않으며, 최종 음성 명령의 명시적 승인이 필요합니다.
- STT 초기화·인식 제한시간, 이전 세션의 오디오 포커스 콜백, 종료 후 오류 콜백, 리스너·엔진 정리를 보완했습니다.
- r2 release 빌드·서명·비밀키 비포함 확인, 실제 API 34 설치·주차 화면·주소 입력의 ‘듣고 있어요’ UI까지 확인했습니다. 전체 음성 입력 완료 및 주문까지의 연결은 확인하지 못했습니다.
- Android Emulator 37.2.13과 별도 공식 36.4.9에서 host / 소프트웨어 렌더러 및 일반·headless 실행을 비교했습니다. 덤프에서 `0xc0000005`와 그래픽 모듈(`libGLESv2.dll`, `libgfxstream_backend.dll`) 충돌을 확인했고, 다른 실행에서는 QEMU 모듈 충돌·ADB/gRPC 단절이 발생했습니다. 모든 실패를 하나의 원인으로 단정하지 않습니다.
- 마이크 선연결 시험 1회는 `AUDIO_INJECTED`로 전송을 마쳤지만 직후 ADB 연결이 끊겼습니다. 오디오 전송 성공을 음성 인식·주문 성공으로 집계하지 않습니다. release 주소→상세주소→주문→승인→조회 **완료된 반복 회차는 0회**입니다.
- 배포 영상은 기존 7분 16초 촬영본입니다. README에는 GitHub 첨부 플레이어를 연결하고 서버 렌더링의 `<video controls>`를 확인했습니다. r2 음성 성공 영상으로 대체하지 않았습니다.

- release는 개발 테스트 서명이며 상용 배포 서명이 아닙니다. APK 크기로 인해 GitHub Releases에 제공합니다.

## r1·r2 공개 음성 SDK 시험 방법

음성 장면에서 앱 함수를 직접 호출해 성공 상태를 만들지 않았습니다. Windows 한국어 합성 음성을 에뮬레이터 가상 마이크에 넣고 공개 SDK의 최종 인식 결과가 주문 엔진으로 들어가는 경로를 사용했습니다. 부분 인식은 실행하지 않으며 중복 최종 결과를 한 번만 처리합니다. 이전 세션 콜백은 세대 번호로 무시하고 종료 시 STT 리스너를 제거합니다.

인식 문장 일부가 ‘비빔밥 한 기업에 배달해 줘’처럼 부정확한 경우도 있었습니다. 최종 상품과 수량, 총액을 다시 확인한 후 별도의 ‘결제 승인’으로 진행합니다. ‘비빔밥 한 개’를 정확히 한 글자도 틀리지 않고 인식했다고 주장하지 않습니다. 음성은 규칙 기반 앱 명령 엔진으로 해석하며, 출품판에서 Gleo LLM이나 추출된 모델을 실행하지 않습니다.

## 11월 13일까지의 시험 한계

- 반복 촬영 중 에뮬레이터 프로세스 종료 또는 ADB/gRPC 연결 정지가 재현됐습니다. 일부 실행에는 그래픽 ColorBuffer 오류가 있었지만 모든 종료의 원인이 확정된 것은 아닙니다. 다른 사용자의 재시작 때문이라고 단정하지 않습니다.
- 공개 음성 SDK의 주문·승인·조회 성공은 debug에서 확보했습니다. 최종 release에서도 추가 마이크 입력을 시도했으나 에뮬레이터 연결 문제가 발생해 같은 과업의 완료를 확인하지 못했습니다. release 음성 반복 안정성은 미완료입니다.
- 목적지·상세주소 음성 UI는 공개 STT에 연결했지만, 이번 추가 에뮬레이터 시험에서 입력 완료를 안정적으로 재현하지 못했습니다. 기존 단위 검사 및 과거 Gleo 연구 성공을 현재 공개 STT 실기 성공으로 대체하지 않습니다. 영상의 주소 장면은 텍스트 검색입니다.
- 새 영상의 픽업은 내비 전송 확인창까지입니다. 과거 NaviHelper 콜백 성공은 기존 연구 기록을 참고하며, 이번 영상의 실제 경로 반영 성공 증거로 제시하지 않습니다.
- 실차·사람 목소리·잡음 환경·상용 서버 부하·실결제·실제 배달권역·실제 매장 주문 접수는 검증하지 않았습니다. 모든 예외 상황을 영상에 촬영하지 않았습니다.
- 0.2.1에서는 Gleo 진입점이 비활성화되어 있었습니다. 11월 15일 공모전의 App Schema 사용 범위를 다시 확인해 0.2.2에서 활성화하고 실제 시스템 Gleo로 재검증했습니다.

## 제출 전 재현 권장 순서

1. 공식 에뮬레이터에서 음성 모델 준비 상태와 마이크 권한을 확인합니다.
2. `apk/README.md`의 release를 설치하고 P단 탐색 → D단 화면 전환을 확인합니다.
3. 마이크 주문 → 총액·상품 확인 → 명시적 승인 → 현황 조회를 반복하고 실패율을 기록합니다.
4. 목적지와 상세주소 음성 입력은 재검증이 끝날 때까지 텍스트·지도 선택 경로를 함께 안내합니다.
5. 신한카드 한도 부족 → 현대카드 재승인, 예약 보류·재개, 완료 사진, 설정과 초기화를 확인합니다.
